# Центр управления бизнесом (платформа вместо n8n)

Русскоязычная веб-панель для компании (торговля + строительство). Ядро на Claude отвечает сотрудникам по данным из 1С, маркетплейсов, Битрикс24 и почты; бот — MAX (запасной Telegram). Сейчас готов **этап 1 — скелет**: панель, подключения с проверкой связи, сотрудники и роли, «Тестирование», журнал, настройки, .bat-установка, демо-режим.

## Кто пользуется и где работает
- Ставит и обслуживает **сисадмин низкой квалификации** на Windows-ВМ. Установка только .bat-файлами, все настройки — формами в браузере.
- Весь интерфейс и все сообщения — **по-русски**. Каждая ошибка: человеческая формулировка + отдельная строка «Что делать». Никаких «ascii codec», голых кодов и трейсбеков в интерфейсе.
- 1С:КА 2.5.26, платформа 8.3.27, опубликована веб-сервером (тонкий клиент по https://IP/ka), расширение установлено. Кабинетов WB/Ozon/Яндекс Маркет несколько; несколько Gmail/Google Drive аккаунтов.

## Стек и структура
Python 3.11, Starlette (не FastAPI), Jinja2, SQLite, uvicorn, httpx, cryptography. Рендер на сервере, без сборки фронтенда, **без внешних библиотек и шрифтов** (панель должна открываться без интернета; CSP `default-src 'self'` — никаких inline-скриптов и стилей).
- `run.py` — служебные команды (serve/start/stop/status/init/check/backup/info/port/selfsigned/resetpw).
- `app/` — main.py (маршруты), config.py, db.py, crypto.py, auth.py, store.py, forms.py, settings_schema.py, backup.py, diagnostics.py, `connectors/` (по файлу на тип подключения), `templates/`, `static/`.
- `tests/` — fake_services.py (поддельные 1С, Bitrix, Google, боты, Claude, маркетплейсы), e2e.py, demo.py (демо-режим), make_screenshots.py.
- `*.bat` в корне (русские имена) и `ИНСТРУКЦИЯ.md` для сисадмина.

## Жёсткие правила (не нарушать)
1. Все пароли и токены шифруются (Fernet, ключ `data/secret.key`, создаётся при первом запуске). В интерфейсе секреты только маской `********t123`. Пустое секретное поле при редактировании = «не менять». Секреты нельзя писать в журнал, логи, сообщения проверок и отчёт — всё идёт через `crypto.redact()`.
2. Права проверяются **на сервере** (`guarded(...)` + `auth.PERMISSIONS`), а не только скрытием в интерфейсе. Менеджер не видит финансы. Формы защищены CSRF.
3. Типы подключений с `single=True` (ядро Claude, боты) нельзя создать дважды: проверка в маршруте, в `store.create_connection` под блокировкой и уникальным индексом в БД.
4. Каждое новое подключение — это `ConnectorType` в `app/connectors/` с описанием, подсказками к полям (где взять токен), функцией `check` и человеческими сообщениями. Форма строится автоматически из `Field`. Регистрация — в `connectors/__init__.py`.
5. Проверки на экране «Тестирование» выполняются параллельно (`asyncio.gather`), сбой одной не роняет остальные. Три состояния: работает / внимание / ошибка; у двух последних — «Что делать».
6. Токены с пробелами/кириллицей/нулевой шириной обрабатывает `forms.process_form` (чистка и понятная ошибка), а не падает на кодировке.
7. .bat: UTF-8 без BOM, **CRLF**, `chcp 65001`, метки на латинице, без скобочных блоков (только goto), каждая ошибка объяснена по-русски. Проверять на настоящей Windows нельзя из Linux — менять осторожно.
8. Пути и `venv`/`data`/`logs`/`.env`/ключи не попадают в архив и в git (см. `.gitignore`).

## Как проверять (обязательно перед любым «готово»)
- `python tests/e2e.py` — сквозные проверки на поддельных сервисах (сейчас 208 из 208). Поднимает панель на порту 8110.
- `python tests/demo.py` (или `демо.bat`) — панель с тестовыми данными на :8099, шпаргалка со значениями печатается в консоль.
- `python tests/make_screenshots.py ПАПКА` — скриншоты (нужен playwright + chromium, только для этого скрипта).
- Кириллицу в формах проверять запросами в %-кодировке, как шлёт браузер, а не сырыми байтами.
- Внешние API проверены только на поддельных сервисах: при переходе к реальным ключам сверить форматы ответов WB, Ozon, Яндекс Маркета, Google, MAX.

## Решение по 1С (важно для этапа 2)
Нужно **прямое онлайн-подключение без выгрузок**: запрос в 1С в момент вопроса, локальной копии данных нет. Два канала: OData (простые справочные запросы) и HTTP-сервис в расширении (сводные вопросы: продажи, остатки, долги, закупки — запрос выполняется внутри 1С). Защита 1С: короткий кэш в памяти (30–60 с), лимит одновременных запросов, отдельный пользователь 1С только на чтение. Пустой состав OData панель показывает как «внимание».
