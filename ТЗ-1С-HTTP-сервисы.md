# ТЗ программисту 1С: HTTP-сервисы расширения для «Центра управления»

Это техническое задание, не инструкция для сисадмина (та — в `ИНСТРУКЦИЯ.md`).
Адресовано программисту 1С, который дорабатывает расширение платформы
«Комплексная автоматизация 2.5.26» (платформа 8.3.27).

## Зачем это нужно

Панель уже умеет проверять связь с 1С через стандартный интерфейс OData —
это справочный интерфейс, годится для списков (справочники, документы), но
**не считает суммы и остатки**: посчитать выручку за месяц через OData либо
неверно (нужно поднимать все документы и суммировать на стороне панели —
медленно и хрупко), либо вообще нельзя (обороты, взаиморасчёты OData не
отдаёт). Поэтому такие сводные вопросы должно считать само расширение —
внутри 1С, средствами обычного запроса — и отдавать уже готовым числом
через свой HTTP-сервис.

## Что уже есть, что нужно сделать

- Публикация расширения через HTTP-сервисы у панели уже поддержана: в
  подключении «1С» есть поле «Путь к HTTP-сервису расширения» (например
  `hs/platforma`), и панель проверяет, что по этому пути (`{адрес
  базы}/{путь}`, обычный `GET` без хвоста) отвечает 2xx — это как раз и
  значит «расширение установлено и опубликовано».
- Сейчас нужен **один новый метод** этого же HTTP-сервиса: `GET
  {адрес базы}/{путь}/summary` — свод для карточки «Финансы» на обзорном
  экране панели. Дальше (по мере разработки бота и ядра Claude) в этот же
  HTTP-сервис будут добавляться другие методы тем же способом (остатки по
  номенклатуре, долги контрагентов, закупки и т. д.) — их пока делать не
  нужно, но НЕ проектируйте сервис так, чтобы это было потом сложно
  добавить (общий модуль для сборки JSON-ответа, общая точка для
  аутентификации — этого достаточно).

## Пользователь и права

Тот же пользователь 1С, что уже используется для OData (в панели — «только
для чтения», раздел 6.1 `ИНСТРУКЦИЯ.md`). Отдельного пользователя под
HTTP-сервис заводить не нужно. Панель обращается методом `GET` с Basic-
авторизацией (логин/пароль этого пользователя), как и к OData.

## Метод `GET .../summary`

**Запрос:** `GET {адрес базы}/{путь-к-hs}/summary`, заголовок `Accept:
application/json`, Basic-авторизация.

**Ответ при успехе:** `200 OK`, `Content-Type: application/json;
charset=utf-8`, тело — плоский JSON-объект:

```json
{
  "revenue_month": 4520000.5,
  "cash_total": 812340.0,
  "stock_value": 9876543.21
}
```

| Поле            | Смысл                                                              | Тип                    |
|-----------------|---------------------------------------------------------------------|------------------------|
| `revenue_month` | Выручка от продаж с начала текущего месяца по сейчас, руб.          | число или `null`       |
| `cash_total`    | Остаток денег на всех счетах и в кассах на текущий момент, руб.     | число или `null`       |
| `stock_value`   | Стоимость товарных остатков на складах на текущий момент, руб.      | число или `null`       |

Требования к числам:
- Обычное число JSON (`4520000.5`), **не строка** (`"4520000.5"` — неверно)
  и без разделителей тысяч.
- Разделитель дробной части — точка. У 1С по умолчанию в JSON может уйти
  запятая (зависит от локали сервера) — это частая ошибка, проверьте на
  тестовом стенде.
- Если какую-то величину сейчас посчитать нельзя (например, ещё не
  настроен нужный регистр) — верните `null` для этого поля, а не `0` и не
  ошибку целиком: панель покажет по этому пункту «внимание», а не поломает
  остальные два.
- Если посчитать нельзя вообще ничего — всё равно верните `200` с тремя
  `null`, а не `4xx`/`5xx` — так панель поймёт, что метод есть, но данных
  пока нет, и объяснит это пользователю понятно, а не как ошибку связи.

**Ответ при внутренней ошибке 1С** (запрос упал по исключению): `500`, тело
— произвольный текст с описанием (можно просто `ОписаниеОшибки(ИнфоОшибки)`),
`Content-Type: text/plain`. Панель покажет пользователю «1С вернула ошибку
при расчёте свода» и посоветует посмотреть журнал регистрации — подробности
из тела ответа никуда, кроме отчёта разработчику, не идут.

**Если метода ещё нет** (расширение не доустановлено) — панель сама
воспринимает `404` как «внимание, ждём расширение», это не нужно отдельно
обрабатывать, это то, что вернёт платформа 8.3, если метод не зарегистрирован.

## Производительность и нагрузка

- Панель кэширует ответ на 30–60 секунд и не отправляет больше одного
  запроса зараз на эту базу — не заваливаем 1С параллельными обращениями,
  но и разгонять запрос специально не нужно.
- Ориентир по времени ответа — до 5 секунд. Если расчёт объективно дольше
  (большая база), заранее скажите — обсудим отдельный кэш на стороне 1С
  (например, регламентное задание раз в несколько минут, которое кладёт
  готовые числа в регистр сведений, а HTTP-сервис их просто читает).
- Запрос должен использовать индексы (регистры остатков/продаж), а не
  обходить документы построчно.

## Как проверить самостоятельно, до передачи панели

1. Открыть в браузере (или Postman/curl) `GET {адрес базы}/{путь}/summary`
   с Basic-авторизацией — должен вернуться `200` и валидный JSON ровно с
   тремя полями выше.
2. Специально проверить месяц, где выручки ещё не было (например, первое
   число месяца, ночь) — `revenue_month` должен быть `0` или маленьким
   числом, но не `null` и не ошибкой.
3. Отключить пользователю доступ к HTTP-сервису — должен вернуться `401`
   или `403`, а не `500`.

## Куда сообщить о готовности

Впишите в панели, в подключении «1С», путь к HTTP-сервису (если он ещё не
был вписан) и нажмите «Проверить связь» на экране «Тестирование» — панель
сама покажет, увидела ли она метод `/summary` и что именно он вернул.
